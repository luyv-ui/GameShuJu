# 投资立项决策系统 V1.0 分阶段开发计划

依据《游戏投资立项决策情报系统 V1.0 需求说明书（AI开发专用）》制定。现有游戏情报库继续承担竞品资料管理，待立项项目独立建模。每阶段完成后验收，再进入下一阶段。

## 阶段 1：项目与风险基础（已完成）

- 建立独立的待立项项目库，支持项目基础信息与风险事实的录入、修改和查看。
- 风险事实包含类别、状态、严重程度、描述和证据链接。仅“已确认且毁灭性”的风险自动触发一票否决。
- 触发否决时系统自动输出“禁止立项”、分数 0，并列出触发项。其他项目保持“资料不足，暂不评级”、分数为空；不得凭缺失的财务数据生成推荐结论。
- 界面展示项目与风险状态，保留原有竞品情报库。项目分数和结论不可人工编辑。
- 验收：项目 CRUD、风险否决优先级、缺失数据不评级均有测试；现有竞品功能和构建通过。

## 阶段 2：财务测算与自动评级（已完成）

- 补齐市场、留存、财务、运营指标的数据模型及来源、时间、地区和币种口径。
- 实现乐观、基准、悲观三情景现金流、IRR、NPV、回本周期和最大亏损测算，并保留输入假设。
- 建立后台可配置的评分权重与阈值。所有分数由原始指标自动计算；缺少关键输入时不输出投资结论，风险否决始终优先。
- 验收：三情景计算和缺失值处理有独立测试，调整配置无需改代码，项目测算能追溯输入依据。报告生成属于阶段 3。

### 已确认的评分口径

- 总分 = 市场机会 20 + 收益能力 30 + 持续性 30 +（风险保留 20 − 已确认风险扣分）。风险扣分最多 20；已确认且毁灭性的风险先于评分触发一票否决，分数归零。
- 基准情景 NPV 不大于 0，或 24 个月内未回本时，即使原始综合分较高，最终分数也封顶 49，结论为“不推荐立项”。
- 正常评分默认 70 分及以上“推荐立项”，50–69 分“谨慎立项”，低于 50 分“不推荐立项”；权重、目标和分界可在评分参数中调整。
- 风险审核、关键市场/用户/商业化指标、数据地区/日期/依据以及三情景假设未齐时，结论为“资料不足，暂不评级”。

### 财务模型口径

- 第 0 月投入前期成本；第 1–24 月按各情景的首月收入、月收入衰减率和固定月运营成本生成现金流。三情景共用前期投入与年折现率。
- NPV 将年折现率换算为有效月折现率；IRR 根据月现金流求解后换算为年化收益率。现金流可能存在多个根或无法求根时，IRR 显示“不可定义”。
- 回本月为累计现金流首次达到非负的月份；24 个月内未达到则显示“未回本”。最大亏损是 0–24 月累计现金流最低点的绝对值。
- 输入是假设值，计算结果不是实际收入预测；币种与数据依据须由录入者确认，不自动换汇。超出 24 个月的长尾收益尚未计入。

## 阶段 3：投资决策界面与报告

- 投资总览、项目详情四个 Tab、赛道对比（目标项目加最多四个竞品）、风险监控中心。
- 自动生成含优势、风险、收益测算、持续性判断和建议的报告，并提供 PDF 导出。
- 验收：五大页面的主要流程可操作，结论与后台计算一致，PDF 与页面数据一致。

## 阶段 4：采集、权限与正式部署

- 将可验证的采集数据接入相应指标；不把公开评论数推断为销量或收入。
- 接入组织身份认证及投资人、分析师、管理员权限，限制所有写接口。
- 按实际数据量和并发需求将 JSON 存储迁移到数据库，落实说明书提出的九类业务表及迁移方案。
- 验收：权限矩阵、迁移、备份恢复和真实钉钉应用联调通过后再开放团队访问。

## 后续待确认的口径

1. 不同赛道的默认财务假设、评分目标和风险扣分应由业务方进一步校准；当前内置值是可编辑的初始模板。
2. 一票否决所需证据与组织审核流程需由业务方确认；当前仅以“已确认且毁灭性”的风险事实触发，未核实风险保持待评估。
